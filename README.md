## ✅ 工程标准

- 每个仓库都能「克隆 → 装依赖 → 一条命令跑起来」；
- 能自动化验证的都写了测试并接入 **GitHub Actions CI**（全部仓库 CI 通过）；
- 未验证过的部分在 README 顶部明写，不藏着。

## 📝 关于「复现」的诚实说明

01–03 对应我在实习与课程中真实参与的项目（MaxKB4j 企业知识库交付、EduRAG 答疑系统部署与效果验证、学生成绩系统上线保障）。原始项目涉及内网环境与企业数据，无法公开；因此我按**同样的业务逻辑、校验规则与接口形态**做了最小可运行的公开复现，把可公开的部分（架构、算法、校验规则、测试用例）开源并接入 CI。每个项目 README 都标注了「复现」范围与已知限制，不夸大原始项目中的角色。
